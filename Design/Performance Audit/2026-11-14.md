# Performance audit — November 14, 2026

The audit targets repeated work while preserving current app behavior. Changes are built and signed locally; nothing was pushed to GitHub or written to personal calendars.

## Improvements

- Share bounded date-formatter caches across event labels, time ribbons, the current-time badge, and localized calendar labels. Keys include locale, calendar identifier, timezone, pattern, and localized-template mode; locale-change notifications clear the cache.
- Index each weather response once, cache up to 128 day ranges, and use exact-hour lookup for midnight connections and hover interpolation. A new response replaces the entire index. Inclusive-start/exclusive-end boundaries, duplicate timestamps, original ordering, and out-of-order response fallback are preserved.
- Cache sorted bank tasks until records or pending writes change. Keep existing sync polling, file formats, revision validation, conflict resolution, write ordering, and retry behavior.
- Skip publishing unchanged bank status/error values. Five stable refreshes previously produced ten UI publications; now they produce zero. Actual synced edits still publish.
- Avoid repainting the entire native calendar for pointer movement over ordinary events. Ruler movement and tooltip appearance/disappearance still redraw; event resize cursors still update on every mouse move.
- Coalesce repeated rich-notes layout measurement requests into a single main-loop pass and guard reentrant measurement. HTML serialization, immediate note binding updates, save timing, focus, and undo are unchanged.
- Reuse editor icon images and the emoji query regular expression instead of recreating them during UI updates.
- Build the shipping app with Swift `-O`. Safety checks remain enabled; no `-Ounchecked` or unsafe math settings are used. The full regression suite also passes with `-O`.

## Synthetic measurements

Median of three executions of the same workloads, hardware, and unoptimized Swift compiler settings. The comparison isolates the source optimizations; it does not include the extra benefit of enabling `-O` for the app. These are helper-workload timings, not end-to-end app frame rates or startup times. Workloads use 552 synthetic forecast hours and 150 tasks in a temporary bank, without reading personal calendar events.

| Workload | Before | After | Speedup |
| --- | ---: | ---: | ---: |
| 3,000 event time labels | 90.37 ms | 9.21 ms | 9.8× |
| 3,000 localized date labels | 90.33 ms | 4.65 ms | 19.4× |
| 10,000 weather day lookups | 305.05 ms | 1.30 ms | 234.7× |
| 1,000 ordered bank reads + duration totals | 743.09 ms | 13.83 ms | 53.7× |
| 5 unchanged bank refreshes | 5.92 ms | 2.03 ms | 2.9× |

The output checksum is unchanged (4,975,150). Benchmark harness: `Tests/Performance/run-benchmark.py`. Raw medians: `2026-11-14-results.json`.

## Verification

- Baseline: 416 existing behavior checks passed before editing.
- Final: 658 checks passed with both the normal and optimized compiler settings. Coverage includes clipboard, cut/delete/undo, grouped bank actions, recurrence snapshots, resizing, view shortcuts, daylight, weather timeouts and toggles, maps, and rich-text notes.
- Added comparisons against uncached/reference implementations for locale/timezone formatting, 23/25-hour DST day boundaries, duplicate and unordered forecast timestamps, missing data, new forecast responses, and bank cache invalidation after sync, reorder, edit, delete, and schedule.
- Offscreen native calendar renders use synthetic events, including overlapping cards, continuous all-day bars, notes, invitation status, and read-only indicators. Before/after pixels are identical in both light and dark appearances.
- The signed optimized app build succeeds.

## Scope and limits

The calendar write paths, permissions/signing identity, Google Drive conflict handling, gesture timing, graph styling, and feature set were not redesigned. Higher-risk changes such as asynchronous EventKit reads, event-layout rewrites, sync debouncing, and delayed note serialization were deliberately left out.

No live calendar edits or network forecast requests were used to validate this audit. Physical trackpad feel, real-provider latency, and full-app CPU/memory/frame-rate measurements remain outside these synthetic checks. The checks reduce regression risk; they do not guarantee that every possible live interaction is covered.
